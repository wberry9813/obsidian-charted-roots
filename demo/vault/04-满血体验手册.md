# Charted Roots 满血体验手册

> 这篇不是功能列表，而是一条从“资料进入 Vault”到“形成可出版研究成果”的完整体验路线。按顺序走一遍，基本等于把 Charted Roots 的主要能力完整体验一次。

## 一、先理解这套 Showcase 的三层模型

Charted Roots 现在不是只有“家谱树”。这个 Demo 把能力拆成三种研究模式：

1. **林氏家族 · 家谱研究**：传统 genealogy 能力最完整，适合观察人物、亲属、婚姻、收养、DNA、媒体、来源、研究日志、统计与报告。
2. **春秋战国 · 历史研究**：重点展示 v2 的时间轴、Process / Period、动态关系、组织归属、官职、Assertion、Citation、Claim 和 BCE 地图。
3. **蜀山 · 世界观**：重点展示 Universe、自定义纪年、fictional Timeline、门派组织、自定义图片地图、地图层级和 transfer。

三套 Workspace 不是三个主题标签，而是三个真正隔离的研究空间。切换 Workspace 后，People / Events / Places / Organizations / Sources / Timeline / Map 的数据边界会一起变化。

## 二、第一阶段：从人物档案进入整个系统

切到 **林氏家族 · 家谱研究**，先打开 [[示例/林氏家族/People/林晨|林晨]]。

这一个人物故意集中了很多高级字段：

- 两段婚姻；
- biological child 与 step-child；
- mentor 自定义关系；
- DNA match；
- 北京 / 上海迁居轨迹；
- JPG、家庭合影和 PDF 证件媒体；
- person-level sources；
- fact-level `sourced_*`；
- education / residence inline events；
- research level 与 collection/group。

在阅读视图里继续观察预置的动态块：

- **Timeline block**：把生命事件、模板和背景 Context 组合在一起；
- **Relationships block**：把亲属与自定义关系集中展示；
- **Media block**：照片与 PDF 不只是附件，而是人物资料的一部分；
- **Sources block**：观察事实来源覆盖；
- **Negative findings block**：研究中“没找到”也能成为结构化成果。

### 对应插件能力

- Entity Profile
- People View
- Relationships View
- Dynamic Note Content
- Fact-level sourcing
- Media Management
- Research status

## 三、第二阶段：把人物变成真正的家族网络

命令面板执行 **Charted Roots: Open Family Chart**，根人物选择林晨。

这套关系数据不是一棵只有父母子女的简单树。你应该能观察到：

- 父系、母系祖辈；
- 兄弟姐妹；
- 第一任与第二任配偶；
- 生物学子女；
- 继子女；
- 收养分支；
- cousin / uncle 等关系计算所需路径。

然后依次试：

- Open new Family Chart；
- Highlight groups；
- Custom relationship overlay；
- Calculate relationship；
- Generate tree for current note；
- Re-layout Canvas；
- PNG / SVG / PDF / ODT export。

## 四、第三阶段：来源不是“参考文献列表”，而是证据网络

打开：

- [[示例/林氏家族/Sources/林氏族谱总卷|林氏族谱总卷]]
- [[示例/林氏家族/Sources/林氏族谱卷三|林氏族谱卷三]]
- [[示例/林氏家族/Sources/林晨出生证明|林晨出生证明]]
- [[示例/林氏家族/Citations/林晨出生日期引用|林晨出生日期引用]]

你会看到几种不同层次：

1. **Source hierarchy**：总卷 → 卷三；
2. **Source classification**：original / derivative / authored narrative；
3. **Information classification**：primary / secondary；
4. **Evidence classification**：direct / indirect；
5. **Source roles**：principal / family / witness；
6. **媒体证据**：照片和 PDF；
7. **事实级来源**：人物 `sourced_birth_date` 等字段；
8. **Citation note**：来源与具体事实之间的可追踪连接。

这时再打开 [[示例/林氏家族/Bases/史料总览.base|史料总览 Base]]，可以从“按类型 / 按仓储 / 按可信度 / 有媒体 / 缺媒体 / 媒体卡片”等角度重新切同一批 Source。

这里的核心设计是：**研究过程本身就是数据，而不是散落在正文中的工作笔记。**

## 八、第七阶段：地图不是一个点，而是“人物—事件—时间”的空间投影

在家谱 Workspace 打开 Map View。

林晨有西安 → 北京 → 上海 → 北京的 residence / education 轨迹，适合测试：

- Journey Mode；
- family journey；
- place hierarchy；
- event marker；
- time slider；
- Place Summary。

然后切换 **蜀山 · 世界观**：

- Map 下拉选择 **蜀山全图**；
- 地图使用 pixel CRS，而不是经纬度；
- 峨眉山拥有 `linked_map`；
- 可以 drill down 到 **峨眉山区域**；
- 子地图拥有 `parent_map + parent_region_*`，可测试 breadcrumb / overlay region；
- 紫云宫是另一处 pixel place。

这部分同时覆盖了真实地图和 fictional image map 两条路径。

## 九、第八阶段：历史研究的 v2 分层

切换 **春秋战国 · 历史研究**，依次打开：

- [[示例/春秋战国/People/齐桓公|齐桓公]]
- [[示例/春秋战国/People/管仲|管仲]]
- [[示例/春秋战国/Events/葵丘会盟|葵丘会盟]]
- [[示例/春秋战国/Processes/春秋争霸|春秋争霸]]
- [[示例/春秋战国/Periods/春秋时期|春秋时期]]
- [[示例/春秋战国/Assertions/管仲任齐相|管仲任齐相]]
- [[示例/春秋战国/Citations/左传支持管仲任相|左传支持管仲任相]]
- [[示例/春秋战国/Claims/齐国霸业结构|齐国霸业结构]]。

这里最重要的是区分：

| 层 | 表达什么 | Demo |
|---|---|---|
| Period | 大的历史阶段 | 春秋时期 |
| Process | 持续过程 | 春秋争霸 |
| Event | 单点/短时事件 | 葵丘会盟、管仲拜相 |
| Assertion | 可带时间区间的事实陈述 | 管仲任齐相、隶属齐国朝廷 |
| Citation | 来源如何支持一个 Assertion | 左传支持管仲任相 |
| Claim | 研究者的解释/判断 | 齐国霸业结构 |

再打开 Temporal Timeline、Relationships、Entity Profile 与 Map，看同一批实体如何在不同 View 中被重新组织。

## 十、第九阶段：世界观不是历史模式的阉割版

切换 **蜀山 · 世界观**，打开 [[示例/蜀山/Universes/蜀山世界|蜀山世界]]。

这页的 Universe 动态块会反向列出：

- People；
- Places；
- Events；
- Organizations；
- Maps。

再看 [[示例/蜀山/People/李英琼|李英琼]]：

- 使用 **蜀山纪年** 而不是 Gregorian/JDN；
- affiliation 到峨眉派；
- mentor 关系；
- fictional timeline；
- transfer block；
- pixel map。

这一套验证的是“同一插件可以把 genealogy schema 和 fictional world schema 放在不同 Workspace 中，各自工作”。

## 十一、第十阶段：Import → Staging → Cleanup → Export

打开 [[实验台/导入样例/README|导入样例说明]]。

## 十三、哪些功能不适合强行塞进离线 Demo

以下能力需要网络或第三方插件环境，所以这里提供入口与数据，但不把它们伪装成离线已验收：

- GeoNames / OSM place lookup；
- Wikidata enrichment；
- Web Clipper；
- Calendarium；
- Dataview；
- Templater；
- Style Settings；
- Excalidraw。

这些属于“集成能力”，与核心数据模型/视图能力分开验收。

## 十四、如果只想做一次最终验收

最短闭环：

1. 林氏家族 → 林晨 → Family Chart；
2. 林晨阅读视图 → Timeline / Relationships / Media / Sources；
3. 人物总览 Base → Multiple marriages / DNA / Needs research；
4. Statistics；
5. Report Wizard → Individual Summary；
6. 春秋战国 → Temporal Timeline → Assertion / Process / Period；
7. 蜀山 → Map → 蜀山全图 → 峨眉山区域；
8. Import Wizard → GEDCOM X JSON → Staging；
9. Book Builder → 林氏家族小史。

这九步能快速判断“满血插件”最重要的能力是否真的都活着。
